## 2. Should you use a backend?

No—not initially. Your portfolio is primarily a content and presentation website.

You don't need FastAPI, NestJS, PostgreSQL, Redis, or Docker just to display your experience and projects.

Use a lightweight external form service for contact messages. Add a custom backend only if you later introduce meaningful functionality such as a content management system, interactive demos requiring server-side processing, or dynamic application features.

## 4. What I would actually build with this stack

- Frontend: Next.js + TypeScript + Tailwind CSS.
- Visual experience: Motion for React, with GSAP only if advanced scroll animation is genuinely needed.
- Content: Local data files for project descriptions, skills, experience, and education.
- Contact: Formspree or Web3Forms.
- Deployment: Vercel with a custom domain.
- Quality: Responsive testing, accessibility checks, metadata, optimized images, and Lighthouse performance audits.

I would avoid adding a database, authentication, state management libraries, or a custom API simply to make the tech stack look more sophisticated. A portfolio is a product in itself; it should demonstrate good engineering judgment.

One final recommendation: Build the portfolio with TypeScript even if some of your personal projects use JavaScript. Your goal is to present a maintainable, production-quality example of your current engineering capabilities.
